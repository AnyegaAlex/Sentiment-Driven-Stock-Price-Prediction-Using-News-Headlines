## General Questions

### What is Tickflow?

Tickflow is an open-source AI-powered stock intelligence platform that combines LSTM neural networks, FinBERT sentiment analysis, and technical indicators to generate stock predictions with 63% accuracy. The platform processes over 10,000 financial news articles daily, providing real-time sentiment analysis and market intelligence.

### Is Tickflow free to use?

Yes, Tickflow is open-source and free to use. The code is available on GitHub under the MIT License. Users can deploy their own instance or use the hosted version. Future Pro and Enterprise tiers may offer additional features.

### How accurate are the predictions?

The platform currently achieves approximately 63% accuracy on over 5,000 tracked predictions. Accuracy is calculated on a 7-day rolling basis. Individual prediction accuracy may vary by stock symbol and market conditions.

### What is the source of the data?

Tickflow uses multiple data sources:

| Source | Data Type |
|--------|-----------|
| **Alpha Vantage** | Stock data, news |
| **Finnhub** | News articles |
| **Yahoo Finance** | Stock data (via yfinance) |
| **FinBERT (Hugging Face)** | Sentiment analysis |

### How often are predictions updated?

Predictions are generated on demand when users request them. The platform does not automatically update predictions; users can generate new predictions at any time. Resolution of predictions occurs 7 days after creation.

### What is the prediction resolution period?

Predictions are resolved 7 days after they are made. On the resolution date, the actual stock movement is compared to the predicted movement to determine if the prediction was correct. This is used to calculate overall accuracy metrics.

### What stock symbols are supported?

### How do I get an API key?

**Development Environment:**
```bash
python manage.py generate_apikey "Development"
```

**Production Environment:**
- Contact the administrator or use the self-service portal
- Generate a key in the Profile section of the web interface

### What are the rate limits?

| User Type | Rate Limit | Scope |
|-----------|------------|-------|
| **Anonymous** | 100 requests/hour | IP-based |
| **JWT User** | 1,000 requests/hour | User-based |
| **API Key** | 200 requests/minute | API Key-based |

Rate limit headers are included in all responses:

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Maximum requests per minute |
| `X-RateLimit-Remaining` | Remaining requests this minute |
| `X-RateLimit-Reset` | Seconds until limit resets |
| `Retry-After` | Seconds to wait (on 429 responses) |

## Financial Questions

### Can I use this for actual trading?

No. Tickflow is for educational and research purposes only. It is not a substitute for professional financial advice. Always consult a qualified financial advisor before making investment decisions.

### What is the accuracy rate?

The current overall accuracy is approximately 63%. This is calculated on a 7-day rolling basis and is based on over 5,000 tracked predictions. Individual predictions may vary.

### How often are predictions updated?

Predictions are generated on demand. There is no automatic update schedule. Users can generate new predictions at any time for any supported symbol.

### What is the difference between LSTM and sentiment predictions?

| Feature | LSTM | Sentiment |
|---------|------|-----------|
| **Input** | 7 features (technical + sentiment) | News sentiment only |
| **Accuracy** | 63% | 55% |
| **Fallback** | Yes | No |
| **When Used** | Primary prediction | Fallback when LSTM unavailable |

### Does the platform support backtesting?

Backtesting is not directly supported. However, the Prediction History API allows users to analyze historical prediction performance. Future versions may include dedicated backtesting features.

## Security Questions

### How is my data protected?

| Aspect | Protection |
|--------|------------|
| **Encryption at Rest** | PostgreSQL encryption, API key hashing (PBKDF2) |
| **Encryption in Transit** | HTTPS/TLS enforced |
| **Authentication** | JWT (60 min access, 7 day refresh) + API keys |
| **Rate Limiting** | 200/min for API keys |
| **Data Retention** | 30 days for logs |

See [Data Protection](8.4-Data-Protection.md) for full details.

### How are API keys stored?

API keys are hashed using Django's PBKDF2 before storage. Raw API keys are never stored.

```python
# Storage format
key_hash = make_password(raw_key)
# Example: pbkdf2_sha256$260000$abc123$def456...
```

### What happens if my API key is compromised?

If your API key is compromised:

1. **Revoke** the key immediately in the Profile section
2. **Generate** a new API key
3. **Update** all applications using the compromised key
4. **Contact** security if suspicious activity is detected

### How can I report a security vulnerability?

1. **Do not** disclose the vulnerability publicly
2. **Email** the security team: anyega.alex.kamau@gmail.com
3. **Include** details about the vulnerability, steps to reproduce, and potential impact
4. **Allow** time for the team to investigate and fix the issue

### What is the API key format?

API keys follow this format:

```
ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz
```

## Troubleshooting

### I'm getting a 401 Unauthorized error

| Cause | Solution |
|-------|----------|
| Invalid API key | Generate a new key |
| Expired JWT | Refresh the token |
| Missing header | Add `X-API-Key` header |

### I'm getting a 429 Too Many Requests error

| Cause | Solution |
|-------|----------|
| Rate limit exceeded | Wait for the period in `Retry-After` header |
| API key rate limit | 200 requests/minute, wait 60 seconds |

### The frontend is not loading

1. Check browser console for errors
2. Verify `VITE_API_BASE_URL` is correct
3. Check backend is running: `curl /health/`
4. Verify API key is valid

### I'm not receiving email notifications

1. Check spam/junk folder
2. Verify email address is correct
3. Check email notification settings
4. Contact support if issue persists
