## Overview

This section provides a complete reference for the Tickflow REST API. The API provides programmatic access to all platform features including stock analysis, technical indicators, sentiment analysis, and LSTM predictions.

---

All API endpoints are relative to the base URL:

```
https://sentiment-driven-stock-price-prediction.onrender.com/api/v1/
```

|-------------|----------|

## Response Format

### Success Response

All successful responses follow this format:

```json
{
  "success": true,
  "data": {
    // Endpoint-specific data
  },
  "code": 200,
  "timestamp": "2026-07-24T10:00:00.123456Z"
}
```

| Field | Description |
|-------|-------------|
| `success` | Always `true` for successful responses |
| `data` | Contains the response payload |
| `code` | HTTP status code |
| `timestamp` | ISO 8601 timestamp of the response |

### Error Response

All error responses follow this format:

```json
{
  "success": false,
  "error": "Human-readable error message",
  "code": 1001,
  "timestamp": "2026-07-24T10:00:00.123456Z",
  "request_id": "abc123def456",
  "details": {}
}
```

| Field | Description |
|-------|-------------|
| `success` | Always `false` for error responses |
| `error` | Human-readable error message |
| `code` | Numeric error code for programmatic handling |
| `timestamp` | ISO 8601 timestamp of when the error occurred |
| `request_id` | Unique identifier for the request (for tracing) |
| `details` | Additional error context (optional) |

## Authentication

### API Key Authentication

API keys are required for all authenticated endpoints. Include the key in the `X-API-Key` header:

```bash
curl -H "X-API-Key: your_api_key_here" \
  "https://sentiment-driven-stock-price-prediction.onrender.com/api/v1/stock-analysis/?symbol=AAPL"
```

### JWT Authentication

For frontend users, JWT tokens are used. Include the token in the `Authorization` header:

```bash
curl -H "Authorization: Bearer your_jwt_token_here" \
  "https://sentiment-driven-stock-price-prediction.onrender.com/api/v1/stock-analysis/?symbol=AAPL"
```

### Public Endpoints

The following endpoints do not require authentication:

| Endpoint | Description |
|----------|-------------|
| `/health/` | Health check |
| `/api/docs/` | Swagger documentation |
| `/api/schema/` | OpenAPI schema |
| `/api/v1/auth/register/` | User registration |
| `/api/v1/auth/login/` | User login |
| `/api/v1/auth/verify-email/` | Email verification |
| `/api/v1/auth/password-reset/` | Password reset request |
| `/api/v1/auth/password-reset/confirm/` | Password reset confirmation |
| `/api/v1/auth/refresh/` | Token refresh |

## Rate Limiting

Rate limits are applied to all authenticated endpoints.

| User Type | Rate Limit | Scope |
|-----------|------------|-------|
| Anonymous | 100 requests/hour | IP-based |
| JWT User | 1,000 requests/hour | User-based |
| API Key | 200 requests/minute | API Key-based |

**Rate Limit Headers:**

| Header | Description |
|--------|-------------|
| `X-RateLimit-Limit` | Maximum requests allowed in the current period |
| `X-RateLimit-Remaining` | Number of requests remaining |
| `X-RateLimit-Reset` | Seconds until the rate limit resets |
| `Retry-After` | Seconds to wait before retrying (on 429 responses) |

For detailed information, see [2.2 Rate Limiting](2.2-Rate-Limiting.md).
