## Data Flow

### Request Flow

```
1. User interacts with React frontend
2. Frontend sends HTTP request to backend API
3. Backend middleware validates authentication (API key or JWT)
4. Request is routed to appropriate view
5. View processes request, may query database or call external APIs
6. Response is returned to frontend
7. Frontend displays data to user
```

### Prediction Flow

```
1. User requests a prediction for a stock symbol
2. Backend fetches price data from yfinance
3. Backend analyzes sentiment using FinBERT
4. Technical indicators are calculated
5. LSTM model generates prediction with confidence score
6. Prediction is saved to database
7. Response is returned to frontend
8. User views prediction in dashboard
```

### News Processing Flow

```
1. User or scheduled task requests news for a symbol
2. Backend checks cache for recent news
3. If cache miss, fetches from Alpha Vantage (primary) or Finnhub (fallback)
4. News articles are deduplicated using SHA-256
5. Sentiment analysis is performed using FinBERT
6. Key phrases are extracted using spaCy
7. Results are cached and stored in database
8. Response is returned to frontend
```

## Key Design Decisions

### 1. Monolithic vs Microservices

**Decision:** Monolithic architecture

**Rationale:**
- Simpler to develop and deploy
- Lower operational overhead
- Single codebase for easier maintenance
- Sufficient for current scale

**Trade-off:** As the platform grows, specific components may be extracted into microservices.

### 2. PostgreSQL vs Other Databases

**Decision:** PostgreSQL

**Rationale:**
- Reliable and proven for production use
- JSONB support for flexible data (preferences, market context)
- Strong performance for read-heavy workloads
- Good support for Django ORM

### 3. Redis for Caching

**Decision:** Redis with memory fallback

**Rationale:**
- In-memory caching for low latency
- Supports rate limiting and session storage
- Optional – falls back to memory cache if Redis unavailable
- Well integrated with Django

### 4. React for Frontend

**Decision:** React

**Rationale:**
- Strong ecosystem and community support
- Component-based architecture promotes reusability
- React Query for robust data fetching
- Recharts for data visualization

### 5. Tailwind CSS for Styling

**Decision:** Tailwind CSS

**Rationale:**
- Utility-first approach reduces custom CSS
- Consistent design system
- Dark mode support built-in
- Small bundle size with PurgeCSS

### 6. LSTM for Predictions

**Decision:** LSTM neural network with sentiment fallback

**Rationale:**
- Effective for time series data
- Combines sentiment + technical indicators
- Fallback to sentiment-only when model is unavailable
- Training on 5+ years of historical data

### 7. FinBERT for Sentiment

**Decision:** FinBERT (fine-tuned BERT)

**Rationale:**
- Pre-trained on financial news
- Fine-tuned for financial sentiment
- Higher accuracy than generic models
- Available via Hugging Face

### 8. API Key Authentication

**Decision:** API key authentication for external access

**Rationale:**
- Simpler than OAuth for API access
- Multiple keys per user
- Rate limiting per key
- Revocation support
- Hashed storage for security

### 9. JWT Authentication

**Decision:** JWT for frontend authentication

**Rationale:**
- Stateless authentication
- Short-lived access tokens (60 minutes)
- Refresh tokens for session extension
- Well integrated with Django REST Framework

### 10. Rate Limiting

**Decision:** Per-user and per-API key rate limiting

**Rationale:**
- Protects against abuse
- Ensures fair resource allocation
- Different limits for different user types
- Headers inform clients of usage

### Scaling Points

| Component | Scaling Strategy |
|-----------|------------------|
| Web Servers | Horizontal scaling (Render auto-scaling) |
| Database | Connection pooling, indexing |
| Cache | Redis cluster, higher memory allocation |
| ML Pipeline | Model optimization, reduced inference time |

### Bottlenecks

| Bottleneck | Mitigation |
|------------|------------|
| Database queries | Indexing, query optimization, caching |
| External API calls | Caching, fallback mechanisms, rate limiting |
