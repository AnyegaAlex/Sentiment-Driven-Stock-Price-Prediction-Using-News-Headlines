# 8.3 Security Headers

**File:** `/wiki/8.3-Security-Headers.md`

---

## Overview

This page provides a comprehensive reference for the HTTP security headers implemented in Tickflow. Security headers are a critical defense layer that protect against various web vulnerabilities including cross-site scripting (XSS), clickjacking, MIME type sniffing, and man-in-the-middle attacks.

---

## Security Headers Overview

### Implemented Headers

| Header | Value | Purpose |
|--------|-------|---------|
| `Content-Security-Policy` | `default-src 'self'; ...` | Prevents XSS and data injection |
| `X-Content-Type-Options` | `nosniff` | Prevents MIME type sniffing |
| `X-Frame-Options` | `DENY` | Prevents clickjacking |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains; preload` | Enforces HTTPS |
| `Referrer-Policy` | `same-origin` | Controls referrer information |
| `X-XSS-Protection` | `1; mode=block` | Prevents reflected XSS (legacy) |
| `Cross-Origin-Opener-Policy` | `same-origin` | Prevents cross-origin attacks |
| `Cross-Origin-Resource-Policy` | `same-origin` | Prevents cross-origin resource loading |
| `Permissions-Policy` | `geolocation=(), microphone=(), camera=()` | Restricts browser features |
| `X-Request-ID` | `unique-request-id` | Request tracing |

## Content Security Policy (CSP)

### Configuration

CSP is implemented in Django middleware to add the header to all responses.

```python
# settings.py
CSP_DEFAULT_SRC = ("'self'",)
CSP_SCRIPT_SRC = ("'self'", "'unsafe-inline'", "https://js.sentry-cdn.com")
CSP_STYLE_SRC = ("'self'", "'unsafe-inline'")
CSP_IMG_SRC = ("'self'", "data:", "https://*.vercel.app", "https://*.onrender.com")
CSP_FONT_SRC = ("'self'", "data:")
CSP_CONNECT_SRC = ("'self'", "https://*.onrender.com", "https://*.vercel.app")
CSP_OBJECT_SRC = ("'none'",)
CSP_BASE_URI = ("'self'",)
CSP_FRAME_ANCESTORS = ("'none'",)
CSP_FORM_ACTION = ("'self'",)
CSP_REPORT_URI = ("/csp-report/",)  # Optional for reporting violations
```

### CSP Report Endpoint (Optional)

```python
# views.py
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
import json

@csrf_exempt
def csp_report(request):
    if request.method == 'POST':
        try:
            data = json.loads(request.body)
            logger.warning(f"CSP Violation: {data}")
        except Exception as e:
            logger.error(f"CSP Report error: {e}")
    return JsonResponse({'status': 'ok'})
```

### CSP Middleware

```python
# middleware/csp.py
class CSPMiddleware:
    def __init__(self, get_response):
        self.get_response = get_response

    def __call__(self, request):
        response = self.get_response(request)
        self.set_csp_headers(response)
        return response

    def set_csp_headers(self, response):
        csp_header = self.build_csp_header()
        response['Content-Security-Policy'] = csp_header

    def build_csp_header(self):
        directives = [
            "default-src 'self'",
            "script-src 'self' 'unsafe-inline' https://js.sentry-cdn.com",
            "style-src 'self' 'unsafe-inline'",
            "img-src 'self' data: https://*.vercel.app https://*.onrender.com",
            "font-src 'self' data:",
            "connect-src 'self' https://*.onrender.com https://*.vercel.app",
            "object-src 'none'",
            "base-uri 'self'",
            "frame-ancestors 'none'",
            "form-action 'self'",
        ]
        return "; ".join(directives)
```

## Strict-Transport-Security (HSTS)

### Configuration

HSTS is configured in Django settings and enforced in production.

```python
# settings.py
# Production only
if not DEBUG:
    SECURE_PROXY_SSL_HEADER = ('HTTP_X_FORWARDED_PROTO', 'https')
    SECURE_SSL_REDIRECT = True
    SESSION_COOKIE_SECURE = True
    CSRF_COOKIE_SECURE = True
    SECURE_HSTS_SECONDS = 31536000  # 1 year
    SECURE_HSTS_INCLUDE_SUBDOMAINS = True
    SECURE_HSTS_PRELOAD = True
```

### HSTS Header

```
Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
```

| Directive | Value | Description |
|-----------|-------|-------------|
| `max-age` | `31536000` | 1 year (recommended minimum) |
| `includeSubDomains` | `True` | Applies to all subdomains |
| `preload` | `True` | Allows preloading in browsers |

### HSTS Preload Submission

To submit your domain to the HSTS preload list:

1. Ensure HSTS is configured with `max-age` of at least 1 year
2. Include `includeSubDomains` and `preload` directives
3. Submit to https://hsts.preload.org

## X-Frame-Options

### Configuration

```python
# settings.py
X_FRAME_OPTIONS = 'DENY'
```

### Header

```
X-Frame-Options: DENY
```

| Value | Description |
|-------|-------------|
| `DENY` | Prevents any site from framing the content |
| `SAMEORIGIN` | Allows framing from same origin only |
| `ALLOW-FROM` | Allows framing from a specific origin (deprecated) |

### Purpose

Prevents clickjacking attacks where malicious sites embed your content in an invisible frame to trick users.

---

## X-Content-Type-Options

### Configuration

```python
# settings.py
SECURE_CONTENT_TYPE_NOSNIFF = True
```

### Header

```
X-Content-Type-Options: nosniff
```

### Purpose

Prevents browsers from MIME-sniffing the content type, which can lead to XSS attacks. Browsers will respect the `Content-Type` header instead of guessing.

## Referrer-Policy

### Configuration

```python
# settings.py
SECURE_REFERRER_POLICY = 'same-origin'
```

### Header

```
Referrer-Policy: same-origin
```

| Value | Description |
|-------|-------------|
| `no-referrer` | Never send referrer |
| `no-referrer-when-downgrade` | Send referrer only on same protocol |
| `same-origin` | Send referrer only to same origin |
| `origin` | Send only origin |
| `strict-origin` | Send origin on same protocol |
| `origin-when-cross-origin` | Send full referrer on same origin, origin on cross-origin |
| `strict-origin-when-cross-origin` | Full referrer on same protocol, origin on downgrade |
| `unsafe-url` | Send full URL always (not recommended) |

### Purpose

Controls how much referrer information is sent with requests, protecting user privacy and preventing information leakage.

## Cross-Origin-Opener-Policy (COOP)

### Configuration

```python
# settings.py
# If using a custom middleware
COOP_POLICY = 'same-origin'
```

### Header

```
Cross-Origin-Opener-Policy: same-origin
```

### Purpose

Prevents cross-origin attacks by isolating browsing contexts from different origins. With `same-origin`, only documents from the same origin can share a browsing context group.

### Values

| Value | Description |
|-------|-------------|
| `unsafe-none` | Default, allows cross-origin sharing |
| `same-origin-allow-popups` | Allows popups to share context |
| `same-origin` | Only same-origin documents share context |

---

## Cross-Origin-Resource-Policy (CORP)

### Configuration

```python
# settings.py
CORP_POLICY = 'same-origin'
```

### Header

```
Cross-Origin-Resource-Policy: same-origin
```

### Purpose

Prevents cross-origin loading of sensitive resources by requiring same-origin for resource access.

### Values

| Value | Description |
|-------|-------------|
| `same-origin` | Only same-origin can load the resource |
| `same-site` | Only same-site can load the resource |
| `cross-origin` | Cross-origin allowed |

## Permissions-Policy

### Configuration

```python
# settings.py
PERMISSIONS_POLICY = {
    'geolocation': '()',
    'microphone': '()',
    'camera': '()',
    'payment': '()',
    'usb': '()',
    'bluetooth': '()',
}
```

### Header

```
Permissions-Policy: geolocation=(), microphone=(), camera=(), payment=(), usb=(), bluetooth=()
```

### Purpose

Controls which browser features and APIs are available to the site, reducing attack surface.

### Common Directives

| Directive | Description |
|-----------|-------------|
| `geolocation` | Geolocation API |
| `microphone` | Microphone access |
| `camera` | Camera access |
| `payment` | Payment API |
| `usb` | USB API |
| `bluetooth` | Bluetooth API |
| `clipboard-read` | Clipboard reading |
| `clipboard-write` | Clipboard writing |
| `fullscreen` | Fullscreen API |
| `picture-in-picture` | Picture-in-Picture API |

## X-XSS-Protection

### Configuration

```python
# settings.py
SECURE_BROWSER_XSS_FILTER = True
```

### Header

```
X-XSS-Protection: 1; mode=block
```

| Value | Description |
|-------|-------------|
| `0` | Disables XSS filtering |
| `1` | Enables XSS filtering |
| `1; mode=block` | Enables filtering and blocks the page if detected |

### Purpose

Controls the browser's built-in XSS filter. While modern browsers have better protection, this header is kept for legacy browser support.

## X-Request-ID

### Implementation

```python
# authentication/middleware.py
class RequestLoggingMiddleware:
    def __call__(self, request):
        request_id = request.headers.get('X-Request-ID', str(uuid.uuid4()))
        request.request_id = request_id
        response = self.get_response(request)
        response['X-Request-ID'] = request_id
        return response
```

### Header

```
X-Request-ID: abc123def456
```

### Purpose

Provides a unique identifier for each request, enabling request tracing and correlation across logs.

## CSP Report Endpoint (Optional)

### Implementation

```python
# views.py
import json
import logging
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
from django.views.decorators.http import require_http_methods

logger = logging.getLogger(__name__)

@csrf_exempt
@require_http_methods(["POST"])
def csp_report(request):
    """Accept CSP violation reports."""
    try:
        data = json.loads(request.body)
        logger.warning(f"CSP Violation Report: {json.dumps(data, indent=2)}")
        return JsonResponse({'status': 'ok'})
    except Exception as e:
        logger.error(f"Error processing CSP report: {e}")
        return JsonResponse({'status': 'error'}, status=400)
```

### URL Configuration

```python
# urls.py
urlpatterns = [
    path('csp-report/', csp_report, name='csp-report'),
]
```
