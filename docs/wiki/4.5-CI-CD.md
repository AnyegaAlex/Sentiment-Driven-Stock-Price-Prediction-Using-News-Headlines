## Overview

This guide covers setting up Continuous Integration and Continuous Deployment (CI/CD) for the Tickflow platform. CI/CD automates testing, building, and deployment processes, ensuring that code changes are validated and deployed quickly and reliably.

---

## CI/CD Pipeline Overview

The CI/CD pipeline consists of the following stages:

```

│                           CI/CD PIPELINE                                   │

│                                                                             │
│  ┌─────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌─────────┐ │
│  │  Code   │───▶│   Test   │───▶│  Build   │───▶│  Deploy  │───▶│ Monitor │ │

│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```

## CI Workflow (ci.yml)

The CI workflow runs on every push to the `main` branch and on pull requests.

**File: `.github/workflows/ci.yml`**

```yaml
name: CI Pipeline

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  # Backend Tests
  backend-tests:
    runs-on: ubuntu-latest
    
    services:
      postgres:
        image: postgres:16
        env:
          POSTGRES_USER: tickflow
          POSTGRES_PASSWORD: tickflow
          POSTGRES_DB: tickflow
        ports:
          - 5432:5432
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
      
      redis:
        image: redis:7
        ports:
          - 6379:6379
        options: >-
          --health-cmd "redis-cli ping"
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5

    steps:
      - uses: actions/checkout@v3
      
      - name: Set up Python
        uses: actions/setup-python@v4
        with:
          python-version: '3.12'
          cache: 'pip'
      
      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements-dev.txt
      
      - name: Run Django migrations
        run: |
          python manage.py migrate
          python manage.py createcachetable
        env:
          DATABASE_URL: postgresql://tickflow:tickflow@localhost:5432/tickflow
          SECRET_KEY: test-secret-key
      
      - name: Run backend tests
        run: |
          pytest tests/ --cov=authentication --cov=stocks --cov-report=xml
        env:
          DATABASE_URL: postgresql://tickflow:tickflow@localhost:5432/tickflow
          REDIS_URL: redis://localhost:6379/1
          SECRET_KEY: test-secret-key
      
      - name: Upload coverage report
        uses: codecov/codecov-action@v3
        with:
          file: ./coverage.xml

  # Frontend Tests
  frontend-tests:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Set up Node.js
        uses: actions/setup-node@v3
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: frontend/package-lock.json
      
      - name: Install dependencies
        run: |
          cd frontend
          npm ci
      
      - name: Run linting
        run: |
          cd frontend
          npm run lint
      
      - name: Run frontend tests
        run: |
          cd frontend
          npm test -- --coverage
      
      - name: Build frontend
        run: |
          cd frontend
          npm run build
        env:
          VITE_API_BASE_URL: https://test-backend.onrender.com
          VITE_API_KEY: test-key
          VITE_USE_MOCK_DATA: true

  # Security Scans
  security-scan:
    runs-on: ubuntu-latest
    needs: [backend-tests, frontend-tests]
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Run Python security scan
        run: |
          pip install bandit safety
          bandit -r . -f json -o bandit-report.json || true
          safety check --json > safety-report.json || true
      
      - name: Run JavaScript security scan
        run: |
          cd frontend
          npm audit --json > npm-audit.json || true
      
      - name: Upload security reports
        uses: actions/upload-artifact@v3
        with:
          name: security-reports
          path: |
            bandit-report.json
            safety-report.json
            frontend/npm-audit.json
```

## Backend Deployment (cd-backend.yml)

The backend CD workflow deploys to Render when changes are merged to `main`.

**File: `.github/workflows/cd-backend.yml`**

```yaml
name: Backend CD Pipeline

on:
  push:
    branches: [ main ]
    paths:
      - 'sentiment_driven_stock_price_prediction_engine/**'
      - 'requirements.txt'
      - 'Dockerfile'
      - 'build.sh'

jobs:
  deploy-backend:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Deploy to Render
        uses: digitalocean/action-doctl@v2
        with:
          token: ${{ secrets.RENDER_API_TOKEN }}
      
      - name: Trigger Render Deployment
        run: |
          curl -X POST \
            -H "Authorization: Bearer ${{ secrets.RENDER_API_TOKEN }}" \
            -H "Content-Type: application/json" \
            -d '{"clearCache": true}' \
            https://api.render.com/v1/services/${{ secrets.RENDER_SERVICE_ID }}/deploys
      
      - name: Wait for deployment
        run: |
          sleep 30
          curl -f https://sentiment-driven-stock-price-prediction.onrender.com/health/ || exit 1
      
      - name: Run post-deployment migrations
        run: |
          # If you have a way to run commands on Render
          # Or run migrations as part of build process
          echo "Migrations are run in the build script"

  # Alternative: Docker-based deployment
  deploy-docker:
    runs-on: ubuntu-latest
    if: false  # Disable if using Render direct deployment
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Set up Docker Buildx
        uses: docker/setup-buildx-action@v2
      
      - name: Login to Docker Hub
        uses: docker/login-action@v2
        with:
          username: ${{ secrets.DOCKER_USERNAME }}
          password: ${{ secrets.DOCKER_PASSWORD }}
      
      - name: Build and push Docker image
        uses: docker/build-push-action@v4
        with:
          context: .
          push: true
          tags: |
            ${{ secrets.DOCKER_USERNAME }}/tickflow-backend:latest
            ${{ secrets.DOCKER_USERNAME }}/tickflow-backend:${{ github.sha }}
      
      - name: Deploy to server
        uses: appleboy/ssh-action@v0.1.5
        with:
          host: ${{ secrets.SERVER_HOST }}
          username: ${{ secrets.SERVER_USERNAME }}
          key: ${{ secrets.SERVER_SSH_KEY }}
          script: |
            cd /app/tickflow
            docker-compose pull web
            docker-compose up -d web
```

## Frontend Deployment (cd-frontend.yml)

The frontend CD workflow deploys to Vercel.

**File: `.github/workflows/cd-frontend.yml`**

```yaml
name: Frontend CD Pipeline

on:
  push:
    branches: [ main ]
    paths:
      - 'frontend/**'
      - '!frontend/**/*.test.js'
      - '!frontend/**/*.spec.js'

jobs:
  deploy-frontend:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Install Vercel CLI
        run: npm install -g vercel
      
      - name: Deploy to Vercel
        run: |
          cd frontend
          vercel --prod --token ${{ secrets.VERCEL_TOKEN }}
        env:
          VERCEL_ORG_ID: ${{ secrets.VERCEL_ORG_ID }}
          VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
          VITE_API_BASE_URL: ${{ secrets.VITE_API_BASE_URL }}
          VITE_API_KEY: ${{ secrets.VITE_API_KEY }}
          VITE_USE_MOCK_DATA: false
          VITE_APP_VERSION: ${{ github.sha }}
      
      - name: Verify deployment
        run: |
          sleep 30
          curl -f https://sentiment-driven-stock-price-predic.vercel.app/ || exit 1
```

## Security Scanning Workflow

**File: `.github/workflows/security-scan.yml`**

```yaml
name: Security Scan

on:
  schedule:
    - cron: '0 0 * * *'  # Daily at midnight
  push:
    branches: [ main ]
    paths:
      - 'requirements.txt'
      - 'frontend/package.json'

jobs:
  dependency-scan:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Python dependency scan
        run: |
          pip install safety
          safety check -r requirements.txt --json --output safety-report.json
      
      - name: JavaScript dependency scan
        run: |
          cd frontend
          npm audit --json > npm-audit.json || true
      
      - name: Report vulnerabilities
        if: failure()
        uses: actions/github-script@v6
        with:
          script: |
            const fs = require('fs');
            const safety = JSON.parse(fs.readFileSync('safety-report.json', 'utf8'));
            const npm = JSON.parse(fs.readFileSync('frontend/npm-audit.json', 'utf8'));
            
            // Process and report vulnerabilities
            const vulnerabilities = [];
            if (safety.vulnerabilities) {
              vulnerabilities.push(...safety.vulnerabilities);
            }
            if (npm.vulnerabilities) {
              vulnerabilities.push(...npm.vulnerabilities);
            }
            
            if (vulnerabilities.length > 0) {
              const message = `Found ${vulnerabilities.length} vulnerabilities:\n${vulnerabilities.map(v => `- ${v.name}: ${v.description}`).join('\n')}`;
              // Send to Slack or create issue
            }

  code-scan:
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Initialize CodeQL
        uses: github/codeql-action/init@v2
        with:
          languages: python, javascript
      
      - name: Autobuild
        uses: github/codeql-action/autobuild@v2
      
      - name: Perform CodeQL Analysis
        uses: github/codeql-action/analyze@v2
```

## Environment Variables and Secrets

### Required GitHub Secrets

| Secret Name | Description | Source |
|-------------|-------------|--------|
| `RENDER_API_TOKEN` | Render API token | Render Dashboard → API Keys |
| `RENDER_SERVICE_ID` | Render backend service ID | Render Dashboard → Service URL |
| `VERCEL_TOKEN` | Vercel API token | Vercel Dashboard → Tokens |
| `VERCEL_ORG_ID` | Vercel organization ID | Vercel Dashboard → Settings |
| `VERCEL_PROJECT_ID` | Vercel project ID | Vercel Dashboard → Project |
| `VITE_API_BASE_URL` | Production backend URL | Render URL |
| `VITE_API_KEY` | Production API key | Generated from backend |

### Setting Secrets in GitHub

```bash
# Add secret via GitHub CLI
gh secret set RENDER_API_TOKEN --body "your-token"

# Or via GitHub Web UI
# Settings → Secrets and variables → Actions → New repository secret
```


## Monitoring Deployments

### Deployment Status Tracking

```yaml
# .github/workflows/deployment-status.yml
name: Deployment Status

on:
  deployment_status:
    states: [success, failure]

jobs:
  notify:
    runs-on: ubuntu-latest
    steps:
      - name: Send notification to Slack
        uses: slackapi/slack-github-action@v1
        with:
          payload: |
            {
              "text": "Deployment ${{ github.event.deployment_status.state }}: ${{ github.event.deployment.payload.url }}",
              "attachments": [
                {
                  "color": "${{ github.event.deployment_status.state == 'success' ? 'good' : 'danger' }}",
                  "fields": [
                    {"title": "Environment", "value": "${{ github.event.deployment.environment }}"},
                    {"title": "Commit", "value": "${{ github.sha }}"},
                    {"title": "URL", "value": "${{ github.event.deployment.payload.url }}"}
                  ]
                }
              ]
            }
```

## Rollback Process

### Automated Rollback on Failure

```yaml
# In cd-backend.yml - Add rollback step
- name: Rollback on failure
  if: failure()
  run: |
    # Rollback to previous deployment
    curl -X POST \
      -H "Authorization: Bearer ${{ secrets.RENDER_API_TOKEN }}" \
      -H "Content-Type: application/json" \
      -d '{"clearCache": true}' \
      https://api.render.com/v1/services/${{ secrets.RENDER_SERVICE_ID }}/rollback
```

### Manual Rollback

```bash
# Render: Go to service → Deployments → Select previous → Deploy
# Vercel: Go to project → Deployments → Select previous → Promote to Production
```

## Performance Optimization

### CI Performance Tips

1. **Cache dependencies** for faster builds
2. **Use parallel jobs** where possible
3. **Run only necessary tests** on PRs
4. **Use smaller test suites** for quick feedback

```yaml
# Cache Python dependencies
- name: Cache pip packages
  uses: actions/cache@v3
  with:
    path: ~/.cache/pip
    key: ${{ runner.os }}-pip-${{ hashFiles('requirements*.txt') }}
    restore-keys: |
      ${{ runner.os }}-pip-

# Cache Node modules
- name: Cache npm packages
  uses: actions/cache@v3
  with:
    path: frontend/node_modules
    key: ${{ runner.os }}-npm-${{ hashFiles('frontend/package-lock.json') }}
```
