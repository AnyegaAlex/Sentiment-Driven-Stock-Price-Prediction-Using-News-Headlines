# 2.1 API Key Management

**File:** `/wiki/2.1-API-Key-Management.md`

## Overview

API keys are required to authenticate requests to the Tickflow API. They provide a secure way to identify and authorize clients accessing the platform. This guide covers generating, using, managing, and securing API keys.

---

## What Are API Keys?

API keys are unique, hashed tokens that identify a user or application making API requests. Each key is associated with a specific user account and can be used to authenticate calls to protected endpoints.

**Key characteristics:**
- Hashed and stored securely using Django's PBKDF2
- Support for multiple keys per user
- Keys can be revoked or deactivated
- Each key has an optional expiry date
- Usage is tracked for monitoring and rate limiting

## Generating an API Key

### Development / Local Environment

API keys are generated using a Django management command:

```bash
python manage.py generate_apikey "Development"
```

**Example Output:**

```
Generated API Key: ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz
```

### Production Environment

For production, generate a key with a descriptive name:

```bash
python manage.py generate_apikey "Production Frontend"
```

## Using an API Key

### Request Header

API keys must be included in the `X-API-Key` header of every authenticated request.

```bash
X-API-Key: ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz
```

### curl Example

```bash
curl -H "X-API-Key: ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz" \
  "https://sentiment-driven-stock-price-prediction.onrender.com/api/v1/stock-analysis/?symbol=AAPL"
```

### Python Example

```python
import requests

API_KEY = "ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz"
url = "https://sentiment-driven-stock-price-prediction.onrender.com/api/v1/stock-analysis/"
headers = {"X-API-Key": API_KEY}
params = {"symbol": "AAPL"}

response = requests.get(url, headers=headers, params=params)
data = response.json()
print(data)
```

### JavaScript Example

```javascript
const API_KEY = "ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz";
const url = "https://sentiment-driven-stock-price-prediction.onrender.com/api/v1/stock-analysis/?symbol=AAPL";

fetch(url, {
  headers: { "X-API-Key": API_KEY }
})
.then(response => response.json())
.then(data => console.log(data));
```

## Multiple Keys Per User

The platform supports multiple API keys per user account. This allows you to:

- Use different keys for different applications (e.g., frontend, mobile app, third-party integrations)
- Rotate keys without disrupting all services
- Revoke a compromised key while keeping others active

**Key naming convention:** Use descriptive names to identify the purpose of each key.

| Key Name | Purpose |
|----------|---------|
| `Production Frontend` | Used by the production React app |
| `Staging Frontend` | Used by staging environment |
| `Mobile App` | Used by the mobile application |
| `Third-Party Integration` | Used for connecting to external services |

## Key Revocation

Revoking a key immediately invalidates it and prevents further use. This is a critical security measure in case of a suspected compromise.

### Process

1. Identify the key to revoke
2. Use the management command or API endpoint to deactivate it

**Management Command Example:**

```bash
python manage.py revoke_apikey "Development"
```

**API Endpoint Example:**

```
DELETE /api/v1/auth/api-keys/{key_id}/revoke/
```

### Effect

- The revoked key will no longer be accepted by the API
- Any requests using the key will return `401 Unauthorized`
- The key can be reactivated if needed (by an admin)

## Security Best Practices

### Never Commit Keys to Version Control

Keys should never be stored in source code or configuration files that are checked into version control. Use environment variables or secure secrets management.

**Bad (committed):**

```javascript
const API_KEY = "ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz";
```

**Good (environment variable):**

```bash
# .env file (not committed)
VITE_API_KEY=ts_abc123def456ghi789jkl012mno345pqr678stu901vwx234yz
```

```javascript
const API_KEY = process.env.VITE_API_KEY;
```

### Use Environment Variables

Store API keys in environment variables or a secrets management service (e.g., HashiCorp Vault, AWS Secrets Manager).

### Rotate Keys Periodically

Regular key rotation reduces the risk of a compromised key being used maliciously.

**Recommended rotation schedule:**
- Production keys: Every 90 days
- Development keys: Every 30 days
- Keys with broad permissions: Every 60 days

### Use Different Keys for Different Environments

Avoid using the same key across development, staging, and production environments. This limits the blast radius of a compromised key.

### Monitor Key Usage

Regularly review key usage logs to detect unusual activity, such as:
- Requests from unexpected IP addresses
- Sudden spikes in request volume
- Requests to unusual endpoints

### Revoke Unused Keys

Periodically audit keys and revoke those that are no longer in use.

## API Key Management Commands

| Command | Description |
|---------|-------------|
| `python manage.py generate_apikey "Name"` | Generate a new API key |
| `python manage.py list_apikeys` | List all API keys for the current user |
| `python manage.py revoke_apikey "Name"` | Deactivate a specific key |
| `python manage.py reactivate_apikey "Name"` | Reactivate a previously revoked key |

## Error Scenarios

| HTTP Status | Error Code | Description |
|-------------|------------|-------------|
| 401 | 1001 | Invalid API key (key not found or inactive) |
| 401 | 1002 | Missing API key (no X-API-Key header) |
| 401 | 1003 | Expired API key (key past its expiry date) |
| 401 | 1004 | Revoked API key (key was deactivated) |

### Example Error Response

```json
{
  "success": false,
  "error": "Invalid or inactive API key.",
  "code": 1001,
  "timestamp": "2026-07-24T10:00:00Z"
}
```
