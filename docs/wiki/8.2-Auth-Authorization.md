# 8.2 Authentication and Authorization

**File:** `/wiki/8.2-Auth-Authorization.md`

## Overview

This page provides a detailed reference for the authentication and authorization mechanisms in Tickflow. Authentication verifies the identity of users and API clients, while authorization controls what authenticated users can access. The platform uses a dual authentication system: JWT for frontend users and API keys for external API access.

---

## Authentication Mechanisms

### Authentication Methods Overview

| Method | Used By | Token Type | Expiry | Storage |
|--------|---------|------------|--------|---------|
| **JWT** | Frontend (React) | Access Token (Bearer) | 60 minutes | localStorage/sessionStorage |
| **JWT** | Frontend (React) | Refresh Token | 7 days | localStorage/sessionStorage |
| **API Key** | External API Clients | X-API-Key header | Configurable (optional) | Hashed in database |
| **Session** | Admin Interface | Session Cookie | 2 weeks | Server-side |

### JWT Authentication

#### Configuration

JWT settings are defined in `settings.py`:

```python
# settings.py
from datetime import timedelta

SIMPLE_JWT = {
    'ACCESS_TOKEN_LIFETIME': timedelta(minutes=60),
    'REFRESH_TOKEN_LIFETIME': timedelta(days=7),
    'ROTATE_REFRESH_TOKENS': True,
    'BLACKLIST_AFTER_ROTATION': True,
    'ALGORITHM': 'HS256',
    'SIGNING_KEY': SECRET_KEY,
    'AUTH_HEADER_TYPES': ('Bearer',),
}
```

#### JWT Flow

```

│                         JWT AUTHENTICATION FLOW                            │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌───────────┐ │
│  │   Client    │───▶│   /login/   │───▶│   Validate   │───▶│  Generate │ │
│  │             │    │   POST      │    │  Credentials │    │   Tokens  │ │
│  └─────────────┘    └──────────────┘    └──────────────┘    └───────────┘ │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Response: { access_token, refresh_token, user }                    │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                      │                                     │
│                                      ▼                                     │
│  ┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌───────────┐ │
│  │   Client    │───▶│   Request    │───▶│   Validate   │───▶│  Attach   │ │

│  └─────────────┘    └──────────────┘    └──────────────┘    └───────────┘ │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Headers: Authorization: Bearer <access_token>                     │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  If JWT expired (401): Refresh token flow                          │   │
│  │  1. POST /refresh/ with refresh_token                              │   │

│  │  3. Retry original request                                         │   │

└─────────────────────────────────────────────────────────────────────────────┘
```

### API Key Authentication

#### API Key Model

```python
# authentication/models.py
class UserAPIKey(models.Model):
    user = models.ForeignKey(User, on_delete=models.CASCADE, related_name='api_keys')
    name = models.CharField(max_length=100)
    key_hash = models.CharField(max_length=128, unique=True, editable=False)
    created_at = models.DateTimeField(auto_now_add=True)
    last_used = models.DateTimeField(null=True, blank=True)
    is_active = models.BooleanField(default=True)
    expires_at = models.DateTimeField(null=True, blank=True)
```

#### API Key Generation

**Management Command:**

```bash
python manage.py generate_apikey "Production Frontend"

# Output:
```

**Programmatic Generation:**

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       API KEY AUTHENTICATION FLOW                           │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ┌─────────────┐    ┌──────────────┐    ┌──────────────┐    ┌───────────┐ │
│  │   Client    │───▶│   Request    │───▶│  Middleware  │───▶│  Validate │ │
│  │             │    │   X-API-Key  │    │  (APIKey)    │    │   Key     │ │
│  └─────────────┘    └──────────────┘    └──────────────┘    └───────────┘ │
│                                                                             │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Headers: X-API-Key: ts_abc123def456ghi789jkl012mno345pqr678stu901  │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                      │                                     │
│                                      ▼                                     │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Validation Steps:                                                   │   │
│  │  1. Check if key exists in database                                  │   │
│  │  2. Verify key hash matches (PBKDF2)                                 │   │
│  │  3. Check if key is active (is_active = True)                       │   │
│  │  4. Check if key has expired (expires_at is null or future)         │   │
│  │  5. Update last_used timestamp                                      │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                      │                                     │
│                                      ▼                                     │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │  Result:                                                             │   │
│  │  - Valid: Attach user to request, allow access                       │   │
│  │  - Invalid: Return 401 Unauthorized                                 │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────────────────────┘
```

#### API Key Middleware

```python
# authentication/middleware.py
class APIKeyMiddleware:
    def __call__(self, request):
        # Skip public paths
        if any(request.path.startswith(path) for path in PUBLIC_PATHS):
            return self.get_response(request)

        # Try JWT first
        try:
            auth_result = self.jwt_auth.authenticate(request)
            if auth_result:
                user, token = auth_result
                request.user = user
                return self.get_response(request)
        except (InvalidToken, TokenError, Exception):
            pass

        # Check API key
        api_key = request.headers.get('X-API-Key')
        if not api_key:
            return JsonResponse(
                error_response('API key required.', 'AUTH_API_KEY_REQUIRED', 401),
                status=401
            )

        # Validate key
        try:
            user_key = None
            keys = UserAPIKey.objects.filter(is_active=True).select_related('user')
            for key in keys:
                if key.validate_key(api_key):
                    user_key = key
                    break

            if user_key:
                request.user = user_key.user
                request.api_key_obj = user_key
                return self.get_response(request)

            return JsonResponse(
                error_response('Invalid or inactive API key.', 'AUTH_INVALID_API_KEY', 401),
                status=401
            )
        except Exception as e:
            logger.error(f"API key validation error: {e}")
            return JsonResponse(
                error_response('Authentication error.', 'AUTH_SERVER_ERROR', 500),
                status=500
            )
```

### Comparison: JWT vs API Key

| Aspect | JWT | API Key |
|--------|-----|---------|
| **Used By** | Frontend (React) | External API clients |
| **Authentication** | Username + Password | API Key header |
| **Token Format** | JWT (signed) | Raw key (hashed in DB) |
| **Expiry** | 60 min (access), 7 days (refresh) | Configurable (optional) |
| **Refresh** | Yes (refresh token) | No (must regenerate) |
| **Multiple Tokens** | No (one session) | Yes (multiple keys) |
| **Revocation** | Automatic (expiry) + blacklist | Manual (revoke) |
| **Security** | Short-lived tokens | Long-lived, revocable |

## Authorization

### Tier-Based Access Control

User tiers determine access to features and endpoints.

| Tier | Features | API Rate Limit |
|------|----------|----------------|
| **Free** | Basic stock analysis, limited predictions | 1000 requests/hour |
| **Pro** | Advanced analysis, more predictions | 2000 requests/hour |
| **Enterprise** | Full access, custom features | Custom |

#### Tier Enforcement

```python
# stocks/views.py (example)
from rest_framework.permissions import BasePermission

class TierPermission(BasePermission):
    def __init__(self, required_tiers):
        self.required_tiers = required_tiers

    def has_permission(self, request, view):
        if not request.user.is_authenticated:
            return False
        return request.user.tier in self.required_tiers

# Usage
class ProFeatureView(APIView):
    permission_classes = [IsAuthenticated, TierPermission(['pro', 'enterprise'])]
```

### Resource-Level Authorization

Users can only access their own data.

```python
# stocks/views.py
class PredictionListView(APIView):
    def get(self, request):
        # Filter by authenticated user
        predictions = Prediction.objects.filter(user=request.user)
        # ... rest of view
```

### Permission Checks

| Check | Description |
|-------|-------------|
| **Authentication** | Is the user authenticated? |
| **Email Verification** | Is the user's email verified? |
| **Onboarding** | Has the user completed onboarding? |
| **Tier** | Does the user have the required tier? |
| **Ownership** | Does the user own the resource? |

### Frontend Authorization

The frontend uses the `ProtectedRoute` component to enforce authorization.

```javascript
// components/auth/ProtectedRoute.jsx
const ProtectedRoute = ({
  children,
  requiredTiers = [],
  requireVerified = true,
}) => {
  const { user, isAuthenticated, isLoading, hasPermission } = useAuth();
  const location = useLocation();

  if (isLoading) {
    return <LoadingSpinner />;
  }

  if (!isAuthenticated || !user) {
    return <Navigate to="/login" state={{ from: location }} replace />;
  }

  if (!user.onboarded && location.pathname !== '/onboarding') {
    return <Navigate to="/onboarding" state={{ from: location }} replace />;
  }

  if (requiredTiers.length > 0 && !hasPermission(requiredTiers)) {
    return <Navigate to="/unauthorized" replace />;
  }

  return children;
};
```

### Authentication Headers

| Header | Value | Purpose |
|--------|-------|---------|

| `X-RateLimit-Remaining` | `185` | Remaining requests |

## Best Practices

### Password Security

```python
# Password validation
AUTH_PASSWORD_VALIDATORS = [
    {'NAME': 'django.contrib.auth.password_validation.UserAttributeSimilarityValidator'},
    {'NAME': 'django.contrib.auth.password_validation.MinimumLengthValidator'},
    {'NAME': 'django.contrib.auth.password_validation.CommonPasswordValidator'},
    {'NAME': 'django.contrib.auth.password_validation.NumericPasswordValidator'},
]
```

### API Key Security

| Practice | Implementation |
|----------|----------------|
| **Never commit keys** | Use environment variables |
| **Rotate keys** | Regularly rotate production keys |
| **Use different keys** | Different keys for different environments |
| **Revoke compromised keys** | Immediate revocation |
| **Monitor usage** | Track key usage and anomalies |

### Session Security

| Practice | Implementation |
|----------|----------------|
| **HTTPS only** | `SESSION_COOKIE_SECURE = True` |
| **HTTP only** | `SESSION_COOKIE_HTTPONLY = True` |
| **SameSite** | `SESSION_COOKIE_SAMESITE = 'Lax'` |
| **Short expiry** | 60 minutes for access tokens |
| **Refresh tokens** | 7 days for refresh tokens |

### JWT Security

| Practice | Implementation |
|----------|----------------|
| **Strong signing key** | `SECRET_KEY` is environment variable |
| **Short-lived access** | 60 minute expiry |
| **Refresh rotation** | Rotate refresh tokens on use |
| **Blacklisting** | `BLACKLIST_AFTER_ROTATION = True` |
| **Algorithm** | HS256 (symmetric) |
