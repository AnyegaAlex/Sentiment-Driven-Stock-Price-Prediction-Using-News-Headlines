# 5.5 Database Schema

**File:** `/wiki/5.5-Database-Schema.md`

---

## Overview

This page provides a comprehensive reference for the Tickflow database schema. The database is PostgreSQL-based and uses Django ORM for model definitions and migrations. The schema covers user management, authentication, stock predictions, news processing, and analytics.

## Table Descriptions

### auth_user

The core user table. Extends Django's default `auth_user` with additional fields.

| Field | Type | Nullable | Default | Description |
|-------|------|----------|---------|-------------|
| `id` | integer | No | Auto | Primary key |
| `username` | varchar(150) | No | - | Unique username |
| `email` | varchar(254) | No | - | Email address |
| `password` | varchar(128) | No | - | Hashed password |
| `first_name` | varchar(150) | Yes | '' | First name |
| `last_name` | varchar(150) | Yes | '' | Last name |
| `nickname` | varchar(50) | Yes | NULL | Optional nickname |
| `bio` | text | Yes | NULL | User biography |
| `persona` | varchar(20) | Yes | NULL | User persona (trader, researcher, etc.) |
| `tier` | varchar(20) | No | 'free' | Subscription tier |
| `email_verified` | boolean | No | False | Email verification status |
| `onboarded` | boolean | No | False | Onboarding completion status |
| `preferences` | JSON | No | '{}' | User preferences (theme, etc.) |
| `created_at` | datetime | No | Now | Account creation timestamp |
| `updated_at` | datetime | No | Now | Last update timestamp |
| `analyses_count` | integer | No | 0 | Number of stock analyses performed |
| `predictions_count` | integer | No | 0 | Number of predictions generated |
| `news_read_count` | integer | No | 0 | Number of news articles viewed |
| `prediction_accuracy` | float | No | 0.0 | Cached prediction accuracy percentage |
| `deletion_requested_at` | datetime | Yes | NULL | When deletion was requested |
| `deletion_scheduled_for` | datetime | Yes | NULL | When account will be deleted |

**Indexes:**
- `email`
- `onboarded`
- `tier`
- `created_at` (descending)

### authentication_userpreferences

Stores user investment preferences and watchlist.

| Field | Type | Nullable | Default | Description |
|-------|------|----------|---------|-------------|
| `id` | integer | No | Auto | Primary key |
| `user_id` | integer | No | - | Foreign key to `auth_user.id` |
| `investment_goal` | varchar(20) | No | 'growth' | Growth, Income, Value, Trading, Retirement |
| `risk_tolerance` | varchar(20) | No | 'moderate' | Conservative, Moderate, Aggressive |
| `experience_level` | varchar(20) | No | 'beginner' | Beginner, Intermediate, Advanced |
| `watchlist` | JSON | No | '[]' | List of stock symbols |
| `email_notifications` | boolean | No | True | Enable email notifications |
| `price_alerts` | boolean | No | True | Enable price alerts |
| `news_alerts` | boolean | No | True | Enable news alerts |
| `theme` | varchar(20) | No | 'system' | Light, Dark, System |
| `language` | varchar(10) | No | 'en' | Language code (en, fr, es) |
| `timezone` | varchar(50) | No | 'UTC' | Timezone |
| `created_at` | datetime | No | Now | Creation timestamp |
| `updated_at` | datetime | No | Now | Last update timestamp |

**Indexes:**
- `user_id`

**Relationships:**
- One-to-One with `auth_user` (cascade delete)

### authentication_userapikey

Stores hashed API keys for external access.

| Field | Type | Nullable | Default | Description |
|-------|------|----------|---------|-------------|
| `id` | integer | No | Auto | Primary key |
| `user_id` | integer | No | - | Foreign key to `auth_user.id` |
| `name` | varchar(100) | No | - | Human-readable key name |
| `key_hash` | varchar(128) | No | - | Hashed API key (PBKDF2) |
| `created_at` | datetime | No | Now | Creation timestamp |
| `last_used` | datetime | Yes | NULL | Last usage timestamp |
| `is_active` | boolean | No | True | Active status |
| `expires_at` | datetime | Yes | NULL | Expiry timestamp |

**Indexes:**
- `user_id`, `is_active`
- `key_hash` (unique)
- `last_used`
- `created_at`

**Unique Constraints:**
- `(user_id, name)` – One name per user

**Relationships:**
- Many-to-One with `auth_user` (cascade delete)

Stores stock predictions generated by the LSTM model.

| Field | Type | Nullable | Default | Description |
|-------|------|----------|---------|-------------|
| `id` | integer | No | Auto | Primary key |
| `user_id` | integer | Yes | NULL | Foreign key to `auth_user.id` |
| `date` | date | No | - | Prediction date |
| `stock_symbol` | varchar(10) | No | - | Stock ticker |
| `headline` | varchar(500) | No | - | Prediction description |
| `sentiment_score` | float | Yes | NULL | Sentiment score (-1 to 1) |
| `predicted_movement` | varchar(10) | No | - | 'up', 'down', 'neutral' |
| `confidence` | float | No | - | Confidence score (0-1) |
| `source` | varchar(20) | No | 'lstm' | 'lstm', 'sentiment' |
| `price_at_prediction` | decimal(15,4) | Yes | NULL | Price when prediction was made |
| `price_at_resolution` | decimal(15,4) | Yes | NULL | Price at resolution |
| `actual_direction` | varchar(10) | Yes | NULL | Actual movement ('up', 'down', 'neutral') |
| `is_correct` | boolean | Yes | NULL | Whether prediction was correct |
| `resolution_date` | datetime | Yes | NULL | When prediction was resolved |
| `price_change_percent` | decimal(10,2) | Yes | NULL | Percentage change |
| `market_context` | JSON | No | '{}' | Market context at resolution |
| `created_at` | datetime | No | Now | Creation timestamp |

**Indexes:**
- `user_id`
- `date`
- `stock_symbol`
- `is_correct`
- `resolution_date`

**Relationships:**
- Many-to-One with `auth_user` (SET NULL on delete)

### authentication_auditlog

| Field | Type | Nullable | Default | Description |

**Indexes:**
- `user_id`, `timestamp` (descending)

**Relationships:**
- Many-to-One with `auth_user` (SET NULL on delete)

## Migrations

### Running Migrations

```bash
# Create migration files
python manage.py makemigrations

# Apply migrations
python manage.py migrate

# Apply specific app migrations
python manage.py migrate authentication

# Check migration status
python manage.py showmigrations
```

### Migration Strategy

| Strategy | Description |
|----------|-------------|
| **Versioned Migrations** | All migrations are versioned in the repository |
| **Rollback Support** | Migrations can be rolled back to previous states |
| **Data Migrations** | Data migrations are included for schema changes |
| **Transactional** | Migrations run within a database transaction |

### Adding a New Model

1. Create the model in `models.py`
2. Run `python manage.py makemigrations`
3. Review the generated migration file
4. Run `python manage.py migrate`

### Rolling Back a Migration

```bash
# Rollback to a specific migration
python manage.py migrate authentication 0004

# Rollback all migrations for an app
python manage.py migrate authentication zero
```

## Database Optimization

### Connection Pooling

```python
# settings.py
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'CONN_MAX_AGE': 60,  # Keep connections alive for 60 seconds
        'OPTIONS': {
            'sslmode': 'require',
            'connect_timeout': 10,
        },
    }
}
```

### Query Optimization

| Technique | Description |
|-----------|-------------|
| **Selective Fields** | Use `only()` and `defer()` to reduce data transfer |
| **Prefetching** | Use `select_related()` and `prefetch_related()` for related data |
| **Bulk Operations** | Use `bulk_create()` and `bulk_update()` for large datasets |
| **Indexing** | Create indexes on frequently queried fields |

### Query Example

```python
# Optimized query
predictions = Prediction.objects.select_related('user').only(
    'id', 'date', 'stock_symbol', 'predicted_movement', 'is_correct'
).filter(is_correct__isnull=False)[:100]
```
