# 4.2 Frontend Deployment (Vercel)

**File:** `/wiki/4.2-Frontend-Deployment-Vercel.md`

---

## Overview

This guide provides step-by-step instructions for deploying the Tickflow frontend to Vercel. Vercel is a cloud platform for frontend applications that provides automatic builds, SSL certificates, and CDN distribution. The frontend is built with React, Vite, and Tailwind CSS.

---

## Prerequisites

| Requirement | Description |
|-------------|-------------|
| GitHub Repository | The project code must be in a GitHub repository |
| Vercel Account | A free or paid Vercel account |
| Backend API Key | A production API key from the backend deployment |
| Backend URL | The production backend URL (Render) |

---

## Step 1: Build the Frontend Locally (Optional)

Before deploying, verify the frontend builds correctly:

```bash
cd frontend

# Install dependencies
npm install

# Build the application
npm run build

# Preview the built application
npm run preview
```

The build output will be in the `dist` directory.

---

## Step 2: Prepare Environment Variables

### Local Development

Create a `.env.production` file in the `frontend` directory:

```bash
# frontend/.env.production
VITE_API_BASE_URL=https://sentiment-driven-stock-price-prediction.onrender.com
VITE_API_KEY=your_production_api_key
VITE_USE_MOCK_DATA=false
VITE_APP_VERSION=1.0.0
```

> **Note:** The `VITE_API_BASE_URL` should not include `/api/v1` – the interceptor adds it automatically.

### Vercel Environment Variables

These will be configured in the Vercel dashboard.

| Variable | Value | Description |
|----------|-------|-------------|
| `VITE_API_BASE_URL` | `https://sentiment-driven-stock-price-prediction.onrender.com` | Production backend URL |
| `VITE_API_KEY` | Your production API key | Generated from backend |
| `VITE_USE_MOCK_DATA` | `false` | Disable mock data in production |
| `VITE_APP_VERSION` | `1.0.0` | Application version |

---

## Step 3: Deploy to Vercel

### Method 1: Vercel Dashboard (Recommended)

1. Go to [Vercel](https://vercel.com) and sign in
2. Click **Add New** → **Project**
3. Import your GitHub repository
4. Configure the project:

| Setting | Value |
|---------|-------|
| **Framework Preset** | Vite |
| **Root Directory** | `frontend` |
| **Build Command** | `npm run build` |
| **Output Directory** | `dist` |
| **Install Command** | `npm install` |

5. Add environment variables:
   - `VITE_API_BASE_URL`
   - `VITE_API_KEY`
   - `VITE_USE_MOCK_DATA`
   - `VITE_APP_VERSION`

6. Click **Deploy**

### Method 2: Vercel CLI

```bash
# Install Vercel CLI
npm install -g vercel

# Navigate to frontend directory
cd frontend

# Login to Vercel
vercel login

# Deploy to production
vercel --prod

# Follow the prompts:
# - Link to existing project? Yes
# - Which project? Select the project
# - Override settings? No
```

---

## Step 4: Configure Environment Variables in Vercel

After deployment, configure environment variables in the Vercel dashboard:

1. Go to your project in Vercel
2. Click **Settings** → **Environment Variables**
3. Add the following variables:

| Name | Value | Environment |
|------|-------|-------------|
| `VITE_API_BASE_URL` | `https://sentiment-driven-stock-price-prediction.onrender.com` | Production |
| `VITE_API_KEY` | Your production API key | Production |
| `VITE_USE_MOCK_DATA` | `false` | Production |
| `VITE_APP_VERSION` | `1.0.0` | Production |

4. Click **Save**
5. Trigger a new deployment for the variables to take effect

## Troubleshooting Common Issues

### Issue: API Connection Failed

**Error:** `Failed to fetch` or `Network Error`

**Solutions:**
- Verify `VITE_API_BASE_URL` is correct in Vercel environment variables
- Ensure the backend is running and accessible
- Check that CORS is configured to allow the Vercel domain
- Verify the API key is valid

**Fix:**
```bash
# Check backend health
curl https://sentiment-driven-stock-price-prediction.onrender.com/health/

# Test API endpoint
curl -H "X-API-Key: your_key" \
  https://sentiment-driven-stock-price-prediction.onrender.com/api/v1/stock-analysis/?symbol=AAPL
```

### Issue: CORS Error

**Error:** `Access-Control-Allow-Origin` missing

**Solutions:**
- Add the Vercel domain to `CORS_ALLOWED_ORIGINS` in backend settings
- Verify `FRONTEND_URL` matches the Vercel URL
- Check that the domain includes `https://`

**Fix:**
```python
# backend/settings.py
CORS_ALLOWED_ORIGINS = [
    "https://sentiment-driven-stock-price-predic.vercel.app",
    # ... other origins
]
```

### Issue: Build Fails

**Error:** Build command fails in Vercel

**Solutions:**
- Check the build logs in Vercel
- Ensure all dependencies are in `package.json`
- Verify Node.js version compatibility (Node.js 20+)
- Check for environment variable usage in build

**Fix:**
```json
// package.json
{
  "engines": {
    "node": "20.x"
  }
}
```

### Issue: 404 Not Found

**Error:** Routes return 404 on refresh

**Solutions:**
- Configure Vercel to handle client-side routing
- Add a `vercel.json` file in the frontend directory

**Fix:**
```json
// frontend/vercel.json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

### Issue: API Key Invalid

**Error:** `401 Unauthorized`

**Solutions:**
- Regenerate a production API key on the backend
- Update the `VITE_API_KEY` environment variable
- Redeploy the frontend

**Fix:**
```bash
# Generate a new API key
python manage.py generate_apikey "Production Frontend"
```

## Custom Domain Configuration

### Add a Custom Domain

1. Go to Vercel Dashboard → Your Project → Settings → Domains
2. Click **Add Domain**
3. Enter your domain (e.g., `tickflowcapital.com`)
4. Follow the DNS verification steps

### DNS Configuration

| Record Type | Name | Value |
|-------------|------|-------|
| CNAME | `www` | `cname.vercel-dns.com` |
| A | `@` | `76.76.21.21` |

### Update Backend CORS

```python
# backend/settings.py
CORS_ALLOWED_ORIGINS = [
    "https://tickflowcapital.com",
    "https://www.tickflowcapital.com",
    # ... other origins
]

CSRF_TRUSTED_ORIGINS = [
    "https://tickflowcapital.com",
    "https://www.tickflowcapital.com",
    # ... other origins
]
```

## Production vs Preview Deployments

### Preview Deployments

Vercel automatically creates preview deployments for pull requests:

- **URL:** `project-name-git-branch.vercel.app`
- **Environment:** Preview (uses preview environment variables)

### Production Deployments

- **URL:** `project-name.vercel.app` or custom domain
- **Environment:** Production (uses production environment variables)

### Environment Variable Overrides

Override variables for specific environments:

| Environment | Variable | Value |
|-------------|----------|-------|
| Production | `VITE_API_BASE_URL` | `https://production-backend.onrender.com` |
| Preview | `VITE_API_BASE_URL` | `https://staging-backend.onrender.com` |

## Monitoring and Analytics

### Vercel Analytics

1. Enable Vercel Analytics in the project settings
2. Add the Analytics script to `index.html` or use the Vercel SDK

### Error Tracking (Sentry)

```javascript
// frontend/src/main.jsx
import * as Sentry from '@sentry/react';

Sentry.init({
  dsn: import.meta.env.VITE_SENTRY_DSN,
  environment: import.meta.env.VITE_ENVIRONMENT || 'production',
  release: import.meta.env.VITE_APP_VERSION,
});
```

### Performance Monitoring

- Use Vercel Speed Insights for Core Web Vitals
- Use Lighthouse to monitor performance
- Set up custom performance monitoring

## Rollback Plan

### Rollback to Previous Version

1. Go to Vercel Dashboard → Your Project → Deployments
2. Find the last stable deployment
3. Click the **...** menu → **Promote to Production**

### Manual Rollback

```bash
# If using Vercel CLI
vercel --prod --force
```
