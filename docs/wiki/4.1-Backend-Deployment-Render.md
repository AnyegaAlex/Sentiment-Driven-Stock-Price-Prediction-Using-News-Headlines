# 4.1 Backend Deployment (Render)

**File:** `/wiki/4.1-Backend-Deployment-Render.md`

---

## Overview

This guide provides step-by-step instructions for deploying the Tickflow backend to Render. Render is a cloud platform that provides PostgreSQL databases, Redis caching, and web services with automatic SSL and scaling.

---

## Prerequisites

| Requirement | Description |
|-------------|-------------|
| GitHub Repository | The project code must be in a GitHub repository |
| Render Account | A free or paid Render account |
| PostgreSQL Database | A Render PostgreSQL instance |
| Environment Variables | All required variables configured |

## Step 1: Prepare the Repository

### Ensure Your Code is on GitHub

```bash
git remote -v
# Should show origin pointing to GitHub
```

### Push the Latest Code

```bash
git add .
git commit -m "Prepare for Render deployment"
git push origin main
```

---

## Step 2: Create a PostgreSQL Database on Render

1. Go to the Render Dashboard
2. Click **New +** → **PostgreSQL**
3. Fill in the details:
   - **Name:** `tickflow-db` or similar
   - **Database:** `tickflow_db`
   - **User:** `tickflow_user`
   - **Region:** Choose the region closest to your users
4. Click **Create Database**
5. Wait for the database to be provisioned
6. Copy the **Internal Database URL** (e.g., `postgresql://user:pass@host:port/db`)

---

## Step 3: Create a Redis Instance on Render (Optional)

1. Go to the Render Dashboard
2. Click **New +** → **Redis**
3. Fill in the details:
   - **Name:** `tickflow-redis`
   - **Region:** Choose the region closest to your users
4. Click **Create Redis**
5. Wait for Redis to be provisioned
6. Copy the **Internal Redis URL** (e.g., `redis://host:port`)

---

## Step 4: Create the Web Service

1. Go to the Render Dashboard
2. Click **New +** → **Web Service**
3. Connect your GitHub repository
4. Fill in the details:

| Setting | Value |
|---------|-------|
| **Name** | `tickflow-backend` (or your preferred name) |
| **Region** | Choose the region closest to your users |
| **Branch** | `main` |
| **Root Directory** | Leave empty (project root) |
| **Environment** | `Python 3` |

### Build Settings

| Setting | Value |
|---------|-------|
| **Build Command** | `./build.sh` |
| **Start Command** | `gunicorn sentiment_driven_stock_price_prediction_engine.wsgi:application` |

### Build Script (build.sh)

The project includes a `build.sh` script in the root directory:

```bash
#!/bin/bash
# build.sh - Render build script

set -e

echo "Installing Python dependencies..."
pip install -r requirements.txt

echo "Collecting static files..."
python manage.py collectstatic --noinput

echo "Running migrations..."
python manage.py migrate

echo "Build complete!"
```

Make the script executable:

```bash
chmod +x build.sh
```

## Step 5: Configure Environment Variables

In the Render Web Service settings, add the following environment variables:

| Variable | Value | Description |
|----------|-------|-------------|
| `SECRET_KEY` | Your Django secret key | Generate a strong, unique key |
| `DEBUG` | `False` | Must be `False` in production |
| `ALLOWED_HOSTS` | `tickflow-backend.onrender.com` | Your Render service URL |
| `DATABASE_URL` | Internal database URL from Step 2 | PostgreSQL connection string |
| `FRONTEND_URL` | `https://sentiment-driven-stock-price-predic.vercel.app` | Your frontend URL |
| `ALPHA_VANTAGE_KEY` | Your Alpha Vantage key | Required for stock data |
| `FINNHUB_API_KEY` | Your Finnhub key | Optional |
| `REDIS_URL` | Internal Redis URL from Step 3 | Optional |
| `ENABLE_LSTM` | `False` | Set to `True` if model is available |
| `SENTRY_DSN` | Your Sentry DSN | Optional |

### Generate a Secret Key

```bash
python -c "import secrets; print(secrets.token_urlsafe(50))"
```

---

## Step 6: Deploy the Service

1. Click **Create Web Service**
2. Render will start building and deploying the service
3. Wait for the deployment to complete (usually 2-5 minutes)
4. Verify the service is running: `https://tickflow-backend.onrender.com/health/`

```bash
curl https://tickflow-backend.onrender.com/health/
```

**Expected Response:**

  "status": "ok",
  "redis": false

## Troubleshooting Common Deployment Issues

### Issue: Database Connection Failed

**Error:** `SSL connection has been closed unexpectedly`

**Solution:**
- Ensure `DATABASE_URL` includes `?sslmode=require`
- Verify the database is provisioned and running
- Check that the database user has correct permissions

**Fix:**
```bash
# In Render environment variables
DATABASE_URL=postgresql://user:pass@host:port/db?sslmode=require
```

### Issue: Relation Does Not Exist

**Error:** `relation "authentication_apikey" does not exist`

**Solution:**
- Run migrations manually:

```bash
# From the Render shell
python manage.py migrate
```

### Issue: ALLOWED_HOSTS Error

**Error:** `Invalid HTTP_HOST header`

**Solution:**
- Add the Render service URL to `ALLOWED_HOSTS`
- Also add the domain without the `.onrender.com` suffix

```bash
ALLOWED_HOSTS=tickflow-backend.onrender.com,.onrender.com
```

### Issue: Build Failing

**Error:** Build command fails

**Solutions:**
- Check the build logs in Render
- Ensure `build.sh` is executable
- Verify all dependencies are in `requirements.txt`
- Check for syntax errors in the build script

### Issue: Port Binding

**Error:** No open ports detected

**Solution:**
- Render expects the service to listen on port 10000
- Update `gunicorn` start command:

```bash
gunicorn sentiment_driven_stock_price_prediction_engine.wsgi:application --bind 0.0.0.0:10000
```

## Render Deployment Tips

### Auto-Deploy

- Render auto-deploys when you push to the connected branch
- Disable auto-deploy if you want manual control
- Use a staging branch for testing

### Scaling

- Render automatically scales the service based on traffic
- Free tier services sleep after inactivity (may cause cold starts)
- Paid tier services stay active and scale automatically

### Logs

- View logs in the Render Dashboard
- Logs are retained for 7 days on the free tier
- Use `Sentry` for long-term error tracking

### Custom Domain

To use a custom domain:

1. Go to Render Dashboard → Your Service → Settings
2. Click **Custom Domain**
3. Add your domain and follow the DNS verification steps
4. Update `ALLOWED_HOSTS` with the custom domain
5. Update `FRONTEND_URL` if needed
