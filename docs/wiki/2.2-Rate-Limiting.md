# 2.3 Authentication Flow

**File:** `/wiki/2.3-Authentication-Flow.md`

## Overview

Tickflow uses two authentication mechanisms:
- **API Key Authentication**: For external API calls (curl, third-party applications, scripts)
- **JWT Authentication**: For the React frontend (user login via username/password)

Both authentication methods are implemented through middleware and are enforced on all protected endpoints except public paths.

---

## Authentication Mechanisms

| Mechanism | Used By | Token Format | Expiry |
|-----------|---------|--------------|--------|
| API Key | External API clients | Hashed key in X-API-Key header | Configurable (default: never) |
| JWT | Frontend (React) | Bearer token in Authorization header | 60 minutes (access), 7 days (refresh) |

---

## API Key Middleware

The API key authentication is implemented in `authentication/middleware.py` and enforces authentication for all non-public endpoints.

### Middleware Flow

```
1. Request arrives at APIKeyMiddleware
2. Check if path is in PUBLIC_PATHS (skip authentication)
3. Try JWT authentication first
4. If JWT fails, check X-API-Key header
5. Hash the key and validate against database
6. If valid, attach user to request and continue
7. If invalid, return 401 Unauthorized
```

### Public Paths (No Authentication Required)

```python
PUBLIC_PATHS = [
    '/admin/',
    '/health/',
    '/api/v1/health/',
    '/api/docs/',
    '/api/schema/',
    '/api/v1/auth/register/',
    '/api/v1/auth/login/',
    '/api/v1/auth/verify-email/',
    '/api/v1/auth/resend-verification/',
    '/api/v1/auth/password-reset/',
    '/api/v1/auth/password-reset/confirm/',
    '/api/v1/auth/refresh/',
    '/api/v1/subscribe/',
    '/api/v1/stock-analysis/',
    '/api/v1/technical-indicators/',
    '/api/v1/sentiment-analysis/',
    '/api/v1/lstm-predict/',
    '/api/v1/symbols/',
]
```

### API Key Validation Process

1. **Extract Key**: Read the `X-API-Key` header from the request
2. **Hash Key**: SHA-256 hash the provided key
3. **Lookup Key**: Query the database for a matching hash
4. **Validate Key**:
   - Check if key is active (`is_active = True`)
   - Check if key has expired (`expires_at` is null or in the future)
   - Verify the key hash matches
5. **Update Usage**: Update `last_used` timestamp
6. **Attach User**: Set `request.user` to the associated user

### Code Example

```python
# authentication/middleware.py
def __call__(self, request):
    # 1. Skip authentication for public paths
    if any(request.path.startswith(path) for path in PUBLIC_PATHS):
        return self.get_response(request)

    # 2. Try JWT authentication
    try:
        auth_result = self.jwt_auth.authenticate(request)
        if auth_result:
            user, token = auth_result
            request.user = user
            return self.get_response(request)
    except (InvalidToken, TokenError, Exception):
        pass

    # 3. Check API key
    api_key = request.headers.get('X-API-Key')
    if not api_key:
        return JsonResponse(
            error_response('API key required.', 'AUTH_API_KEY_REQUIRED', 401),
            status=401
        )

    # 4. Validate key
    try:
        user_key = None
        keys = UserAPIKey.objects.filter(is_active=True).select_related('user')
        for key in keys:
            if key.validate_key(api_key):
                user_key = key
                break
        
        if user_key:
            request.user = user_key.user
            request.api_key_obj = user_key
            return self.get_response(request)
        
        return JsonResponse(
            error_response('Invalid or inactive API key.', 'AUTH_INVALID_API_KEY', 401),
            status=401
        )
    except Exception as e:
        logger.error(f"API key validation error: {e}")
        return JsonResponse(
            error_response('Authentication error.', 'AUTH_SERVER_ERROR', 500),
            status=500
        )
```

## JWT Authentication Flow

JWT authentication is used by the frontend when users log in with a username and password.

### Login Flow

```
1. User submits username/password to /api/v1/auth/login/
2. Backend validates credentials
3. If valid, returns JWT access token (60 min) and refresh token (7 days)
4. Frontend stores tokens in localStorage/sessionStorage
5. Frontend includes access token in Authorization header for subsequent requests
6. Backend validates JWT on each request
7. On expiry, frontend uses refresh token to obtain new access token
```

### Token Structure

**Access Token:**
- Expires in 60 minutes
- Used for API authentication
- Contains user ID and token type

**Refresh Token:**
- Expires in 7 days
- Used to obtain new access tokens
- Stored securely

### Login Response

```json
{
  "success": true,
  "data": {
    "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
    "user": {
      "id": 29,
      "username": "moses",
      "email": "user@example.com",
      "email_verified": true,
      "onboarded": true
    }
  }
}
```

### Token Refresh Flow

```
1. Access token expires (401 Unauthorized)
2. Frontend sends refresh token to /api/v1/auth/refresh/
3. Backend validates refresh token
4. If valid, returns new access token
5. Frontend retries original request with new access token
```

### Refresh Request

```json
POST /api/v1/auth/refresh/
{
  "refresh": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

### Refresh Response

```json
{
  "success": true,
  "data": {
    "access": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

```python

```

## Security Headers

The platform includes security headers to protect against common vulnerabilities:

| Header | Value | Description |
|--------|-------|-------------|
| `X-Content-Type-Options` | `nosniff` | Prevents MIME type sniffing |
| `X-Frame-Options` | `DENY` | Prevents clickjacking |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | Enforces HTTPS |
| `X-Request-ID` | `unique-request-id` | Enables request tracing |
